# 阶段一至五架构说明

## 范围

本实现覆盖基础对话、RAG 知识增强、MCP 工具调用、两个有界任务模板，以及第五阶段 Planner／Executor／Reviewer 三角色协作。二手书、课表、课程评价和开课班使用模拟数据，不连接真实学校系统。多 Agent 只支持课程联合推荐和 2～4 本二手书比价；主动提醒、真实业务写操作和任意自由工具编排尚未实现。

三个角色是同一服务进程内职责分离的确定性组件，不是三个独立进程或三个自由对话模型。第五阶段增加的是计划交接边界、原始证据复核和失败关闭，而不是扩大第四阶段的业务范围。

## 请求链路

```text
浏览器 / 终端
      |
      v
ChatService
  |-- 隐私检测：敏感值直接拦截，不保存、不外发
  |-- 阶段边界：主动提醒明确拒绝；无执行模板的组合任务不伪装完成
  |-- 会话工具提示：仅保留最近成功工具名称，最多用于接下来 3 个追问机会
  |-- MultiAgentCoordinator：先识别课程推荐或多书比价的固定模板
  |       |-- PlannerAgent：解析当前轮约束并生成、校验白名单计划
  |       |       `-- 参数不足／不支持的硬约束 -> 澄清，不调用工具
  |       |-- ExecutorAgent：再次校验后顺序调用白名单 MCP 工具
  |       |       `-- 确定性筛选；原始 ToolEnvelope 深拷贝只保留在内存
  |       `-- ReviewerAgent：核对计划／轨迹／证据并独立复算
  |               |-- 通过 -> 发布 task_result 和正文
  |               `-- 拒绝／异常 -> review_failed，不发布候选推荐
  |-- ToolRouter：结合当前问法与工具提示确定单工具意图，并重新提取最小参数
  |       |-- 二手书参数不足 -> 直接澄清，不调用工具或语言模型猜库存/价格
  |       |-- 白名单 MCP Client -> 进程内 MCPServer
  |       |-- MCP 工具 -> 统一结构化 envelope
  |       `-- 工具数据 -> 模型受约束整理；校验失败时确定性格式化
  |-- 会话解析：为“联系电话呢？”等短追问补上上一轮主题
  |-- KnowledgeBase：本地向量与 BM25/关键词混合检索并执行置信度门控
  |       |-- 无可靠命中 -> 校园问题拒绝猜测
  |       `-- 有可靠命中 -> 组装证据与来源元数据
  |-- ChatOllama.stream（默认，本机 qwen3:4b）
  |       |-- 原生模型片段 -> NDJSON delta
  |       `-- 流结束后证据校验失败 -> replace 为本地摘录
  `-- 网页：呈现正文、三角色状态和脱敏工具轨迹；服务内部保留来源、告警与原始证据
```

## 组件职责

- `campus_agent/agent.py`：总控路由、多 Agent 协调器接入、阶段边界、连续追问、二手书澄清与防猜测保护、知识缺口策略、原生模型流和流后证据校验；仅保存最终回答。
- `campus_agent/planning.py`：`TaskPlan` 和 `TaskExecution`；固定任务模板、最多 6 次工具调用、步骤状态、课程周次／时间／校区／学期及评价约束、2～4 本书各一本最低组合与预算核验；同时保存供 Reviewer 使用的内存证据副本。
- `campus_agent/multi_agent.py`：Planner／Executor／Reviewer 角色契约、完整计划校验、计划指纹、三角色事件、课程和二手书独立复算，以及 Reviewer 未通过时的失败关闭。
- `campus_agent/prompts.py`：系统规则、证据数据边界和 RAG 输入构造。
- `campus_agent/llm.py`：ChatOllama、Responses API 与 OpenAI-compatible Chat Completions 适配及错误处理。
- `campus_agent/safety.py`：敏感信息检测与外发前二次脱敏。
- `campus_agent/sessions.py`：带 TTL 和容量限制的内存会话；另外只记录最近一次成功工具的名称，不保留工具参数，并为接下来的最多 3 个追问机会提供领域提示。
- `campus_agent/server.py`：静态页面、NDJSON 对话流、JSON API、安全响应头和本机知识重建保护。
- `campus_agent/tool_router.py`：识别五类单工具意图，覆盖二手书交易表达，提取书名/价格/演示编号/星期/课程名/校区，并识别尚无模板的组合任务边界。
- `campus_agent/mcp/server.py`：创建官方 SDK `MCPServer`，注册五个校园工具并提供 stdio 入口。
- `campus_agent/mcp/client.py`：Agent 使用的 SDK `Client(server)` 适配器、工具白名单及结果结构校验。
- `campus_agent/mcp/repositories.py`：只读模拟数据访问与现有 `KnowledgeBase` 封装；二手书查询包含常见教材简称归一化。
- `campus_agent/rag/loaders.py`：Markdown、TXT、HTML、DOCX 和可选 PDF 文本解析。
- `campus_agent/rag/chunker.py`：按标题、段落和句子切分，并限制片段长度。
- `campus_agent/rag/index.py`：带模型名、维度、版本和语料指纹的原子化 float32 向量索引。
- `campus_agent/rag/retriever.py`：融合余弦相似度、BM25 和关键词覆盖率，随后执行门控、排序与结果去重。
- `web/`：不依赖 CDN 的响应式聊天界面；展示回答正文、三角色卡、脱敏工具轨迹和任务计划／步骤状态，不展示内部引用、原始工具数据或可靠性告警。

## MCP 调用链

```text
用户单工具请求
  -> SessionStore（可选：最近成功工具名称，最多覆盖接下来 3 个追问机会）
  -> ToolRouter（当前问法优先，结合提示确定工具；参数始终从当前问题重新提取）
  -> 参数不完整时返回澄清，终止工具与 LLM 调用
  -> MCPToolClient（只允许五个名称）
  -> 官方 SDK Client(server) 进程内协议连接
  -> MCPServer @tool 参数校验
  -> CampusToolRepository
  -> structuredContent 统一 envelope
  -> Agent 一致性校验与自然语言回答
```

外部 Host 使用同一个 `MCPServer` 的 stdio 传输。当前网页服务不开放 MCP HTTP 端点，因此不需要在第三阶段引入网络鉴权、跨域或公开端口。

工具上下文只是一项短期领域提示，不是参数记忆。成功调用二手书工具后，“那高数呢？”可以继续路由到二手书查询，但系统不会把上一轮的“概率论”或价格条件静默带入当前调用。一次查询失败不会建立工具上下文；当前消息包含课表、课程评价或校园知识等明确意图时，当前意图优先。若交易问法只有“有卖二手书吗？”或“多少钱？”而没有可验证的书名，Agent 返回澄清说明，并阻止语言模型生成库存或价格结论。

## 第四阶段执行链

课程推荐：完整匿名课表 → `course_offering_search` 候选开课班 → `course_review_search` 聚合评价 → 按 `course_id` 连接 → 时间／周次／学期／校区／评分筛选 → 评分、评价数量排序。只查询某一天的课表不足以证明全部课程无冲突，因此模板始终读取完整课表。没有编号时显式使用 `DEMO001` 并声明是演示课表；未指定校区时从课表确定，不能确定则停止。

时间冲突要求星期相同、闭区间周次有交集，以及半开时间区间 `[start,end)` 有严格交集；前课结束恰好等于后课开始不算重叠。“周二下午没课”表示在周二下午寻找无冲突班次，不等价于整段下午空闲；“避开／不要周二下午”排除与该时段重叠的班次。候选有多次上课时，所有上课时间都必须通过约束和冲突检查。未知时间、缺失／无效评价、已选同名课及学期或校区不符的候选会排除，不自动放宽约束。“不点名”只允许 `attendance_requirement=none`，“评分高”默认至少 4.5/5。

多书比价：解析 2～4 个明确书名 → 每书调用一次 `secondhand_book_search` → 每书各选一本且记录编号不能重复 → 计算可检索最低组合总价 → 校验单本上限和总预算。简称归一化后重复的教材、缺书或超预算不会被声称为符合；比较范围只是工具实际返回的模拟记录，不是全市场最低价。

执行时最多调用 6 次白名单工具；依赖工具失败则标记后续步骤 `skipped`，返回失败而非部分伪推荐。两个模板的字段、时间和预算语义保持不变，详细数据边界见 `PHASE4.md`。

## 第五阶段协作与审核链

Planner 使用确定性解析器生成两个模板之一，不调用工具。`validate_plan` 对计划编号、任务类型、标题、约束集合和值域、步骤结构、工具顺序、状态及调用上限做完整校验。Executor 接收计划后再次校验并在私有副本上执行，因此不能追加工具或静默改变 Planner 的约束。

Executor 每次调用 MCP 后，除脱敏轨迹外，还在内存中保存原始 `ToolEnvelope` 的深拷贝。Reviewer 不调用 MCP，也不直接相信 Executor 的 `items` 或答案：它核对 Planner 计划、运行副本、工具轨迹和原始证据的一致性。课程任务会重新运行课程筛选并比较状态、项目和正文关键事实；二手书任务会独立枚举每书各一本且编号不重复的组合，重算最低总价与预算结论。证据必须明确为 `demo`，且不能包含禁止字段。

协调器只在 Reviewer 完成后发送 `task_result` 和答案 `delta`。Reviewer 拒绝、异常或没有执行报告时，最终状态为 `review_failed`、结果数量为 0，并用统一停止说明替代 Executor 候选正文。工具失败若被确认如实停止且没有推荐项，可以通过安全审计，但任务状态仍保持 `failed`。完整角色与失败边界见 `PHASE5.md`。

## RAG 可靠性策略

1. 每份源文档记录权威级别、核验状态、核验日期、时效等级和原始 URL。
2. 文档与问题统一使用 `qwen3-embedding:4b` 生成归一化向量，同时从现有片段文本计算 BM25 与关键词覆盖率。
3. 向量命中继续受绝对阈值约束；向量不足时，仅允许具有明确关键词覆盖且满足全部复合概念的 BM25 结果兜底。融合排序后再执行相对阈值、同源数量和近重复限制。
4. 有命中时，`qwen3:4b` 只根据选中的证据自然概括，并在内部回答中逐段标注 `[来源N]`。
5. 原生模型片段会立即以 `delta` 输出，但属于待校验草稿；完整回答必须使用有效引用，并与对应证据存在实质内容支持。不满足或流异常时发送 `replace`，由本地证据摘录覆盖临时文本。只有校验后的最终回答保存到会话；中断的草稿不保存。
6. 权威级别、核验状态和时效告警保留在服务内部结果中；按当前网页产品要求，展示层只呈现正文并移除引用、来源对象和告警。

这一策略偏保守：宁可明确说“不知道”，也不把语言流畅当作事实正确。

## 索引生命周期

索引记录解析器、切分器、向量格式、嵌入模型和维度，以及源文件、旁路元数据和切分参数的组合指纹。启动时若版本、模型或指纹不一致，自动重建。向量以归一化 float32 little-endian Base64 保存；写入采用同目录临时文件加原子替换，避免异常中断留下半份索引。

## 接口

- `GET /api/health`：模型、知识库与 MCP 工具状态，阶段标记为 `[1,2,3,4,5]`；`planning.mode=bounded-multi-agent` 声明两类任务及 6 次调用上限，`multi_agent` 声明三个角色和 Reviewer 失败关闭。
- `GET /api/knowledge/search?q=...`：只检索，不生成答案。
- `POST /api/chat`：`application/x-ndjson` 对话流。普通事件为 `start`、若干 `delta`、可选 `replace`、`done`；单工具事件为 `start -> tool_start -> tool_result -> delta -> done`。工具事件只携带脱敏参数、状态、数据模式、数量和说明。
- 多 Agent 任务事件为 `start -> agent_start(planner) -> agent_result(planner) -> plan -> agent_start(executor) -> (step_start -> tool_start -> tool_result -> step_result)... -> agent_result(executor) -> agent_start(reviewer) -> agent_result(reviewer) -> task_result -> delta -> done`；纯筛选／汇总步骤不发送工具事件。`step_result` 区分完成、失败和跳过，`task_result` 还可返回 `review_failed`。Reviewer 完成前不发送正文。
- `POST /api/session/clear`：清空指定内存会话。
- `POST /api/knowledge/rebuild`：重建索引，仅接受本机请求；浏览器请求还必须精确同源。

所有接口同源提供，不开放跨域；响应包含 CSP、禁止嵌入和禁止 MIME 嗅探等安全头。

## 已知边界

- 没有用户登录、权限体系和持久化会话。
- 没有独立向量数据库；索引直接保存为本地版本化 JSON。开发验收曾使用 4 份文档、534 个片段和对应的 2560 维向量，公开仓库不附带这些本地资料和索引。
- 没有 OCR；扫描 PDF 会报告无法提取文本。
- 没有实时同步学校系统；知识来自部署方自行导入的本地资料，来源属性和日期以旁路元数据为准。
- 二手书、课表、课程评价与开课班是 `data/tools` 中的模拟 JSON，分别为 100 条书籍、2 个匿名学生共 12 条课表安排、8 门课程评价和 12 个开课班；没有真实库存、真实成交价格、真实学生课表或真实评价，所有结果必须保留模拟数据警示。
- 不支持任意自由多工具任务、多时段复杂组合、学分／教师／配送等缺少可靠字段的硬约束；三个 Agent 不扩大两个模板的范围。
- 不支持主动提醒、后台定时任务、主动通知或真实业务写操作。
- 自动测试使用确定性的嵌入和聊天替身，覆盖模型参数、向量索引、原生流时序、证据校验与替换协议；正常运行时默认连接本机 `qwen3:4b` 和 `qwen3-embedding:4b`。
