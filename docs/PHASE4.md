# 第四阶段：有界任务规划与多工具执行

## 范围与数据

第四阶段在现有对话、RAG 和官方 MCP 系统上增加任务拆分、顺序执行、条件筛选和结果汇总，不包含第五阶段的 Planner／Executor／Reviewer 多 Agent。任务计划来自确定性的两个模板，不采纳语言模型自由生成的工具名、代码或任意执行步骤。

当前业务工具数据全部本地模拟：100 条二手书、2 个匿名学生共 12 条课表安排、8 门聚合评价、12 个开课班。所有任务结果必须说明模拟数据，不能代表真实库存、用户本人课表、正式开课或学校选课承诺。本地阶段验收曾沿用 4 份资料、534 个知识片段的知识库，不将模拟课程数据混入正式知识源；公开仓库不附带这些本地资料和索引。

## 模板一：课程推荐

示例：

```text
推荐一门 DEMO001 周二下午评分高且不点名的通识课
推荐 DEMO002 周二下午评分至少4.5分的通识课
推荐 DEMO001 避开周二下午的通识课
推荐 DEMO001 周二14:00–16:00、评分高的通识课
```

执行计划：

1. `student_schedule_query`：读取指定匿名学生的完整课表，不只读用户提到的星期。
2. `course_offering_search`：按课程名／分类和校区获取开课班。
3. `course_review_search`：获取同类课程聚合评价。
4. 按 `course_id` 连接开课班与评价，核验所有硬约束。
5. 按评分降序、评价数量降序、班次编号排序，默认返回最多 3 个，明确“一门”时最多 1 个。

支持约束：演示编号、一个星期／时段或有效起止时间、校区、最低评分、不点名、低工作量。默认分类为“通识”；明确“专业拓展”时按对应分类查询，也可通过书名号或引号提供一个明确课程名。

默认值必须透明：未提供演示编号时使用 `DEMO001`，回答声明这不是用户真实课表；未指定校区时从完整课表确定，不能确定则停止。“评分高／口碑好”默认至少 4.5/5，明确评分必须在 0～5 范围；未提出评分约束时不暗加 4.5 的门槛。低工作量只接受“低／较低”。“不点名”只接受结构化字段 `attendance_requirement=none`，不能把“偶尔点名”视作符合。

时间含义：

- 上午为 08:00–12:00，下午为 13:00–18:00，晚上为 18:00–23:00。
- “周二下午没课”按“寻找周二下午可选且不冲突的课程”处理，并说明不意味着整段下午空闲。
- “避开／不要／不安排周二下午”会排除与指定时段重叠的班次，再检查其他上课时间是否冲突。
- 一个班次有多次上课时，所有上课时间都要通过约束，不能只看到一个空闲时间就推荐。
- 冲突要求同一天、上课周次有交集且时间有严格交集。时间使用半开区间 `[start,end)`，例如前课 15:35 结束、后课 15:35 开始不算重叠；周次使用闭区间，互不相交的周次不冲突。

排除或停止策略：候选时间未公布、学期／校区不符、已选同名课、地点缺失、无匹配评价、无有效评分或与已选课程冲突时不推荐，并汇总排除原因。学生课表本身周次／时间不完整、学期不一致或工具失败时无法证明无冲突，任务停止；不把“查不到”当作“没课”，不自动放宽条件。

## 模板二：多本二手书比价

示例：

```text
比较《高等数学》和《线性代数》，总预算50元，每本最多30元
帮我买高数、线代、概统各一本，总预算80元
```

解析 2～4 个明确书名；每书查询一次 `secondhand_book_search`，支持可选单本上限与总预算，预算范围 0～10000 元。每个书名各选一本，使用工具实际返回的候选记录计算最低组合，记录编号不能重复。回答列出实际教材、版本、价格、编号、校区、组合总价及预算符合／不足情况。

比较范围只限实际检索返回的模拟记录，不是全校园或真实市场最低价。近名检索可能包含辅导书，必须核对输出的实际书名、版本和教材类型；仅查询比价，不下单、不联系卖家。某书无候选、归一化后两个简称是同一本教材、不能形成不同记录组合，或总价超预算时不会声称满足。版本、成色、校区、作者、配送、联系方式等复杂硬约束缺少该模板的可靠筛选方式，会要求改用单本查询或澄清，不伪装已经筛选。

预算使用数字；无法解析的中文金额、负数、反向预算要求或多组矛盾预算会澄清。`每本预算20元` 不会误算成两本总预算20元；多书查询中无前缀的 `50元以内` 明确解释为总预算。

课程备选每门只保留一个班；多条结果是独立备选，不是可同时选修的组合。指定学期、指定周次、多校区／多演示学生、未支持的评分上限／反向评价要求和跨业务组合会澄清；具体时间范围与上午／下午等条件矛盾时也不会执行。已选课与候选课之间的学期、所有上课时间和实际周次仍必须核验。

多书任务不把最后一本的参数写入单书追问上下文；下一轮仍需明确提供当前书名。

## 可观察执行与错误处理

`GET /api/health` 当前提供阶段 `[1,2,3,4,5]`、两类任务和 `max_tool_calls=6`。NDJSON 对话流在最终正文前提供计划、步骤及工具状态；第五阶段在这些事件外增加三个角色事件，详见 `PHASE5.md`：

```text
start → plan → step_start → tool_start → tool_result → step_result
             → 后续步骤／工具 → task_result → delta → done
```

纯本地筛选和汇总步骤没有工具事件。步骤状态包括 `pending/running/completed/failed/skipped`；最终任务状态包括 `completed/no_result/failed`。Agent 普通结果保留 `task_plan/task_status/tool_calls`，失败时普通结果模式为 `task_error`。流开始时模式为 `task`，失败需结合 `task_result.status` 判断，不能仅凭 HTTP 200 或流开始的模式认定任务成功。

最多 6 次白名单工具调用；依赖工具失败后停止筛选并跳过后续步骤。网页只展示脱敏参数、状态、结果数量和简短说明，不发送完整工具 `items`。正式回答只来自已执行、已校验的工具数据，任务模板无需模型编造推荐。

RAG 仍可输出真实原生 `delta`，但这些内容是未完成证据校验的临时草稿。流结束后校验，异常时 `replace` 整体替换为有来源的本地降级回答；只有最终回答保存到会话，中断草稿不保存。任务执行轨迹和 RAG 草稿都不是多 Agent 协作证明。

## 不支持与后续边界

- 任意自由多工具组合、多个星期／时段的复杂组合、学分／教师／单双周等缺少可靠字段的额外硬约束。
- 正式选课、占位、退课、实际购书或联系卖家。
- 真实学号、真实学生信息和需要登录的学校系统。
- 第五阶段多 Agent、主动提醒、后台定时任务和主动通知。

真实接入前需补齐授权、登录与最小权限、稳定编号、学期／周次、数据更新和评价治理；不应直接把模拟 JSON 改成真实个人数据。
