# 阶段一至五验收说明

场景清单更新日期：2026-09-25。以下是验收方法与预期；本轮实际结果见末尾记录与 `PROGRESS.md`，不能把预期当作未经执行的通过证明。

## 自动化验收

在项目根目录执行：

```powershell
$env:PYTHONDONTWRITEBYTECODE = "1"
python -m unittest discover -s tests -v
```

覆盖范围：

- Markdown CRLF front matter、GB18030 文本、DOCX 与失败文档隔离。
- 长文本切分上限、向量索引保存/复用、损坏向量拒绝、失败构建不覆盖旧索引，以及解析版本、切分配置或嵌入模型变更后的自动重建。
- 中文校园问题检索、无关问题不命中。
- RAG 来源、知识缺口拒答、短追问，第四阶段成功模板和约束边界，以及第五阶段 Planner／Executor／Reviewer 职责隔离、证据复算与主动提醒拒绝。
- 密码等敏感消息不保存、不检索、不外发。
- 默认 Ollama 模型配置、`OllamaEmbeddings` 参数，以及 ChatOllama 普通调用和原生流内容处理。
- Responses API 与 Chat Completions 请求格式、脱敏、截断和异常响应。
- 健康检查、静态页面、聊天、搜索、JSON 校验、知识重建同源保护、安全响应头，以及模型完成前即可收到首个 `delta` 的真实流时序。
- RAG 原生临时草稿流与流结束后证据校验；不合格回答或流异常通过 `replace` 被本地摘录整体覆盖；只有最终回答进入历史，中断草稿不保存。
- 五类单工具意图路由、参数提取、模拟数据过滤和统一 envelope。
- 二手书 100 条模拟记录的数量与编号唯一性、常见教材简称、丰富交易问法、无效书名拒绝，以及最近成功工具上下文的 3 次追问机会边界。
- 二手书参数不足时的普通与流式澄清保护：不调用 MCP 工具，也不调用语言模型猜测库存或价格。
- 官方 SDK `MCPServer` 的五工具发现、SDK `Client(server)` 真实协议调用与 `structuredContent` 校验。
- Agent 主动调用、工具白名单、真实学号拦截，以及 `tool_start/tool_result` 脱敏流事件。
- 第四阶段完整课表 → 开课班 → 聚合评价依赖链、默认演示编号声明、课程编号连接、时间／周次／学期／校区校验、严格不点名与评分条件、未知字段排除及失败不伪推荐。
- 2～4 本书各一本的多次工具调用、单本／总预算、重复简称、缺书／超预算边界和最多 6 次调用上限。
- `plan/step_start/step_result/task_result` 事件、执行状态和网页计划卡。
- `agent_start/agent_result` 三角色事件顺序、Reviewer 前不发布任务正文、篡改结果拒绝、复核异常失败关闭，以及流中断不保存半成品。

验收时必须分别记录：完整回归结果、第三／四阶段新增测试结果、MCP 协议测试结果和浏览器手工结果。若官方 SDK 未安装，协议测试会显示 skipped，此时不能把第三／四阶段标记为完整运行验收通过。必须使用安装依赖的同一个 Python 解释器，不能把另一个环境缺 SDK 的跳过结果当作完成证明。

## 手工验收场景

### 1. 基础对话

输入：`你好`

预期：默认由本机 `qwen3:4b` 流式回复。可以说明已实现 MCP 工具、第四阶段固定任务模板和第五阶段三角色协作，但不得声称连接真实校园系统、支持任意规划或主动提醒。

### 2. 正式本地文档 RAG

输入：`公共自习室允许占座吗？`

预期：`mode=rag`。网页直接显示回答正文，不显示 `[来源N]`、来源卡或告警；服务内部完成引用与证据校验。需要审计时，可在终端执行同一问题，检查本地 DOCX、`authority=official` 和 `verification_status=source-provided`。

### 3. 连续追问

依次输入：

1. `公共自习室允许占座吗？`
2. `校外人员呢？`

预期：第二问沿用公共自习室主题，回答“禁止校外人员使用”。

### 4. 待核验资料警告

输入：`体测当天需要携带校园卡吗？`

预期：可以使用用户提供的体测整理材料；服务内部来源保持 `community / pending-review`。网页按当前展示要求只显示正文，不展示来源和可靠性告警；需要审计时在终端查看来源元数据，并仍应将该材料视为待核验内容。

### 5. 学生手册 PDF

输入：`学生证丢失后怎么办？`

预期：命中《华南理工大学2026本科生手册》的相应页码片段；在未安装 `pypdf` 的环境中也应通过 `.pdf.txt` 缓存完成检索。

### 6. 知识缺口

输入：`图书馆校外访问怎么使用？`

预期：没有可靠知识时明确表示不能猜测，不调用模型记忆补全校园事实。

### 7. 二手书 MCP 工具

输入：`帮我找一本30元以内的高等数学二手书`

预期：Agent 主动调用 `secondhand_book_search`；网页先显示工具调用卡，再显示以“以下为模拟数据”开头的结果；每项价格不超过 30 元，不出现联系方式。

当前 `data/tools/secondhand_books.json` 应有且仅有 100 条模拟记录，编号唯一。该数量用于扩大检索覆盖面，不代表真实校园库存或生产数据。

### 7.1 截图三问回归

在同一会话中依次输入：

1. `有卖概率论二手书吗？`
2. `有卖概率论吗？`
3. `有卖概率论与数理统计吗？`

预期：三次均调用 `secondhand_book_search`，不得把“吗”提取为书名，也不得绕过工具让语言模型回答“没有”。三次均应命中模拟记录 `BOOK-DEMO-005`（《概率论与数理统计》，演示价格 20 元），并明确提示结果来自模拟数据。

### 7.2 丰富问法、简称与连续追问

以下问法应进入二手书工具：`有人卖大学物理吗？`、`出售数据结构`、`求购操作系统`、`我想买离散数学`、`高等数学哪里能买到？`。输入 `那高数呢？`、`概统有吗？` 等简称或省略表达时，在最近成功的二手书工具上下文内应重新从当前问题提取书名，并由仓储层将常见简称归一化后检索。

最近成功工具的名称最多为接下来的 3 个追问机会提供领域提示；它不保存或复用上一轮书名、价格。连续经过 3 个未刷新工具上下文的其他问答后，第 4 个省略式追问不应继续继承旧工具领域；新的成功工具调用会重新建立上下文。

### 7.3 参数不足与防猜测

输入：`有卖二手书吗？`

预期：返回澄清提示，要求补充明确书名；不得以 `book_name=吗` 调用工具，也不得调用语言模型生成“有货”“无货”或价格结论。

在成功查询一本书后继续输入：`多少钱？`

预期：仍要求当前轮补充明确书名，不静默复用上一轮书名。只有取得二手书工具结果后，回答才能陈述本地模拟记录中的库存和演示价格；任何结果均需保留模拟数据警示。

### 8. 匿名课表 MCP 工具

输入：`查询 DEMO001 周二的课表`

预期：调用 `student_schedule_query`，只返回 `DEMO001` 的周二模拟安排。输入疑似真实长学号时，应在工具调用前拦截，且不写入会话历史。

### 9. 课程评价 MCP 工具

输入：`电影艺术赏析的课程评价怎么样？`

预期：调用 `course_review_search`，显示聚合模拟评分、数量和特点，并明确标注模拟数据。

### 10. 第四阶段课程推荐

输入：`推荐一门周二下午没课、评分高且不点名的通识课`

预期：执行计划依次调用 `student_schedule_query`（完整课表）、`course_offering_search` 和 `course_review_search`，随后筛选并汇总。未给演示编号时明确声明默认 `DEMO001`，不是用户本人课表；“评分高”默认至少 4.5/5，“不点名”只接受结构化 `none`。回答说明“周二下午没课”是寻找该时段可选且无冲突班次，不代表整段下午空闲。所有结果明确模拟数据，不以一个评价工具结果伪造推荐。

继续验收：

- `推荐 DEMO002 周二下午评分至少4.5分的通识课`：全部候选与该演示课表的校区、学期、星期、时间和周次匹配后才推荐。
- `推荐 DEMO001 避开周二下午的通识课`：排除指定时段重叠的开课班，不能反向推荐周二下午课。
- 检查相邻时间端点和不重叠周次：15:35 结束与 15:35 开始不算时间重叠，互不相交周次不冲突。
- 尚未公布时间、无可匹配评价、偶尔点名、已选同名课或冲突班次不应作为满足硬约束的推荐。
- 工具失败或课表本身无法解析时任务失败，后续步骤跳过，不输出“无冲突”伪结论；没有符合项时不偷偷降低评分或放宽点名限制。

### 10.1 第四阶段多书比价

输入：`比较《高等数学》和《线性代数》，总预算50元，每本最多30元`

预期：先显示计划，再分别查询两本书；每书各选一本，记录编号不得重复，输出实际模拟记录、各价、总价与预算结论。只能称为“实际检索返回记录的最低组合”，不能称真实市场最低价。

边界：2～4 个书名可以比较；5 个、模糊书名、归一化后重复简称会要求澄清或停止；单本／总预算不足或缺一本时明确无完整符合组合。单本查询保持原功能。多书执行不将最后一本的参数用于下一轮省略问法。

### 10.2 第五阶段多 Agent 与后续边界

输入：`查课表和二手书后安排购书路线`、`推荐周二下午和周四晚上的课`、`推荐2学分且指定老师的通识课`

预期：对没有固定模板或缺少可靠字段的约束明确澄清／拒绝，不只执行部分工具后声称完成。

输入：`请让 Planner、Executor 和 Reviewer 三个 Agent 协作，DEMO001 推荐一门周二下午评分高且不点名的通识课`

预期：依次显示 Planner、Executor、Reviewer；Planner 只生成固定白名单计划，Executor 只按计划调用三个 MCP 工具，Reviewer 根据当前请求内存中的完整工具证据独立复算。Reviewer 完成前不发布任务结论；审核通过后才显示推荐。

输入：`每天主动提醒我考试`

预期：`mode=not_implemented`，明确主动提醒尚未实现，不产生后台任务或声称已经安排提醒。

### 11. 隐私拦截

输入一条只用于本地测试的虚构值，例如：`我的统一认证密码是 DEMO_SECRET_123，怎么激活账号？`

预期：`mode=sensitive_input_blocked`；消息不进入会话历史，不发送远程模型。不要使用真实密码测试。

### 12. 页面与移动端

- 顶部显示模型、知识库与 MCP 工具状态。
- 回答按原生模型流逐步出现；RAG `delta` 是待校验临时草稿，不能当作已核验结论。网页不出现内部引用、来源卡或告警。
- 正常事件顺序为 `start -> delta... -> done`；证据校验失败时为 `start -> delta... -> replace -> done`，收到 `replace` 后必须整体覆盖旧文本。
- 单工具事件顺序为 `start -> tool_start -> tool_result -> delta -> done`；工具卡只显示脱敏参数、数据模式、结果数量与简短状态，不显示完整 items。
- 多 Agent 任务事件顺序为 `start -> Planner agent_start/result -> plan -> Executor agent_start -> step/tool events -> Executor agent_result -> Reviewer agent_start/result -> task_result -> delta -> done`。Reviewer 前不得出现任务正文；纯筛选步骤无工具事件。失败显示失败／跳过状态，不能仅凭 HTTP 200 判定任务成功。
- 健康检查阶段为 `[1,2,3,4,5]`、五个工具、三个角色和两类有界任务，最多 6 次工具调用。
- 重建按钮可用，跨来源请求被拒绝。
- 390px 宽视口无横向溢出，发送、清空和推荐问题可操作。
